# Keel in Chrome — MV3 side-panel extension

A self-contained Manifest V3 Chrome extension whose side panel mirrors the
**Chat / Convert** panel in Claude-in-Chrome, branded as Keel. It is a
**local-first demo**: there are no runtime network requests, no API keys, no
accounts, and no dependencies to install. Page text is read from the active
tab, and answers are generated by deterministic rules inside the panel.

## Load it unpacked (Chrome / Chromium 114+)

1. Download and unzip `https://keel-desktop.vercel.app/keel-extension.zip`
   (or use the copy of this folder in the repository). The ZIP contains
   `manifest.json` at its root — do **not** point Chrome at a nested folder.
2. Open a new Chrome tab and go to `chrome://extensions`.
3. Turn on **Developer mode** (top-right toggle).
4. Click **Load unpacked**.
5. Select the folder that directly contains `manifest.json`
   (`…/keel-extension/` or the extracted ZIP folder).
6. Click the Keel toolbar icon ( puzzle piece → Keel if it is hidden), or
   right-click a web page and choose **Ask Keel about this page** or
   **Convert this page with Keel**.

The extension works on regular `http:` / `https:` pages. Chrome restricts
content-script access on `chrome://`, Web Store, and some built-in pages; on
those, the panel falls back to the tab title and URL and says
“limited page access” in the context chip.

## Permissions explained

| Permission | Why it is requested |
| --- | --- |
| `activeTab` | Read the tab the user is currently viewing when the panel asks for context. |
| `sidePanel` | Open and display `sidepanel.html` beside the page. |
| `scripting` | Allowed for future scripted context improvements; this build uses a declarative content script instead. |
| `storage` | Persist model, approval mode, settings, pending context-menu action, and local session history. |
| `tabs` | Find the active tab/window and open fallback tabs or tab groups. |
| `contextMenus` | Add the two right-click menu items that open the panel. |
| `unlimitedStorage` | Keep a generous local history of sessions (capped at 60 in code). |
| `<all_urls>` host permission | Let the read-only content script run on web pages so the panel can summarize them. |

No permission is used to send data anywhere. There is no `fetch`, `XMLHttpRequest`,
analytics, telemetry, or external font/script import in the extension.

## What is in the panel

- Top bar with Keel starburst, **New** and **History** actions, and an
  `Elios · Free` account chip with a menu (opens the Keel web app in a new tab
  only when clicked, plus a local Settings panel).
- Tool tabs: **Keel**, **Keel Code**, **Everyday tools**, **Background tasks** —
  each swaps the six quick-action suggestions.
- Page context chip with title/domain/word count, a **Refresh** control, and
  **Copy as markdown** for the full page context.
- Prominent **Chat [K] Convert** pill toggle; `K` toggles when not typing.
- Chat mode: deterministic, useful page summary — title, domain, highlighted
  selection, word count, extracted key terms, detected page type, and a next step.
- Convert mode: structured markdown deliverable with summary, action items,
  a key-facts table, key-term frequencies, and next steps.
- Six marketing quick actions (metrics, Drive, calendar, competitor deck, CRM
  call logging, promotional-email cleanup) that fill and run a tailored prompt.
- Composer: multiline input (Enter sends, Shift+Enter adds a line), `+` attach
  menu (**Use page selection** / **Use full page**), simulated mic with a clear
  “no audio recorded” note, model selector (Mythos / Opus / Sonnet / Haiku),
  approval-mode selector, and send/Stop button.
- Local session history drawer (restore or delete sessions) and a settings
  drawer (streaming, auto-save, keyboard hints, reduced motion, reset).
- Keyboard accessible, `aria` labels, focus-visible styles, warm cream/ink
  visual design. No `alert()` calls.

## How the demo AI works

`content.js` clones the page body into a detached node, removes scripts,
styles, navigation, forms and other noise, and returns up to ~30,000 characters
plus the current selection. It never modifies the live page.

`sidepanel.js` then:

1. Tokenizes the text and scores word frequency (stopwords removed) to pick
   key terms.
2. Extracts the strongest 1–3 sentences by term overlap and sentence length.
3. Detects the surface (analytics, docs, calendar, Drive, mail, CRM, commerce,
   or general web page) from the domain.
4. Detects intent from your prompt or the quick action (metrics, competitors,
   CRM, email, code, and so on) and chooses matching analysis, next step, and
   action items.
5. Builds a markdown answer and types it out gradually for a natural feel.

The same input always produces the same body of text (only the “captured at”
timestamp changes). Model and approval-mode choices are recorded in the answer
footer and persisted, but they do not contact a provider — this is an
intentional local demo, not a live AI integration.

## Known limitations

- Not a live model: answers are rule-based summaries, not generated by an LLM.
- No real dictation; the mic is a labeled simulation and records no audio.
- Tab grouping uses `chrome.tabs.group` when the browser supports it; otherwise
  tabs are opened normally. `OPEN_TAB_GROUP` is available over the internal
  message bus but is not exposed as a panel button.
- `chrome://` and Web Store pages cannot be read by content scripts; the panel
  degrades to title/URL context.
- Session history is local to this extension profile; it does not sync with
  the Keel desktop app or web app.
