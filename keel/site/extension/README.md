# Keel in Chrome — MV3 side-panel extension (v1.0.0)

A self-contained Manifest V3 Chrome extension whose side panel mirrors a
**Chat / Convert** workspace, branded as Keel. It is a **local-first demo**:

- No runtime network requests, no API keys, no accounts, no dependencies.
- Page text is read read-only from the active HTTPS tab.
- Answers are generated by deterministic rules inside `sidepanel.js`.
- Conversation history and preferences stay in `chrome.storage.local`.

This folder is the exact package that becomes `keel-extension.zip`.

## Load it unpacked (Chrome / Chromium 114+)

1. Get the ZIP: `https://keel-desktop.vercel.app/keel-extension.zip` (or use
   this folder from the repository). `manifest.json` is at the archive root —
   do **not** point Chrome at a nested folder.
2. Open a new tab and go to `chrome://extensions`.
3. Turn on **Developer mode** (top-right toggle).
4. Click **Load unpacked**.
5. Select the folder that directly contains `manifest.json` (this folder, or
   the extracted ZIP folder).
6. Click the Keel toolbar icon (puzzle piece → Keel if hidden). The panel opens
   via `sidePanel.setPanelBehavior({ openPanelOnActionClick: true })`, so it
   also works after the service worker has been suspended. Alternatively,
   right-click a page and choose **Ask Keel about this page** or
   **Convert this page with Keel**; both open the panel and prefill a prompt.

The panel reads page text only on `https://` web pages. On `chrome://` pages,
the Web Store and other restricted pages it falls back to the tab title and
URL and displays "limited page access" in the context chip. Nothing is modified
on the page.

## Permissions explained

Every requested permission maps to a concrete behavior in this build:

| Manifest key | Why it is requested |
| --- | --- |
| `sidePanel` | Register and display `sidepanel.html` as an extension side panel. |
| `storage` | Persist model profile, approval mode, settings, pending context-menu action, and up to 60 local sessions. |
| `activeTab` | Grant temporary access to the tab the user is acting on when a panel action is invoked, without a broad install-time grant. |
| `tabs` | Find the active tab/window (for page title/URL metadata and the side-panel window ID) and open a fallback tab if the side panel API is unavailable. |
| `contextMenus` | Add the two right-click menu items that open the panel. |
| `host_permissions: https://*/*` | Allow the read-only content script to run on HTTPS pages and let the worker message it with `tabs.sendMessage` to collect page text. |
| `content_scripts: https://*/*` | Declaratively inject `content.js` into the **top frame** only, at `document_idle`. Narrower than `<all_urls>`: no `file:`, `ftp:`, `chrome:` or extension pages. |

Deliberately **not** requested: `scripting` (unused — injection is declarative),
`unlimitedStorage` (sessions are capped at 60), `downloads`, `notifications`,
`cookies`, `webRequest`, and `<all_urls>`. No permission is used to send data
anywhere. There is no `fetch`, `XMLHttpRequest`, `WebSocket`, analytics or
telemetry in the extension, and no remote code: the explicit extension-pages
CSP is `script-src 'self'; object-src 'self'`.

## What is in the panel

- Top bar with the Keel starburst and **New** / **History** actions, plus a
  clearly labeled local-demo menu (the only link opens the Keel web app if the
  user clicks it; Settings is local).
- Tool tabs: **Keel**, **Keel Code**, **Everyday tools**, **Background tasks** —
  each swaps the six example prompt suggestions.
- Page context chip with title/domain/word count, a **Refresh** control, and
  **Copy as markdown** for the full page context.
- Prominent **Chat / Convert** toggle; `K` toggles when not typing.
- Chat mode: a rule-based page summary — strongest sentences, key terms,
  detected page type, highlighted selection and a suggested next step.
- Convert mode: a structured markdown deliverable with summary, action items,
  a key-facts table, key-term frequencies and next steps.
- Composer: multiline input (Enter sends, Shift+Enter adds a line), a `+`
  attach menu (**Use page selection** / **Use full page**), a clearly labeled
  simulated mic that records no audio, a local profile selector
  (Mythos / Opus / Sonnet / Haiku — demo labels, not connected to any AI
  provider), an approval-mode selector, and a send/Stop button.
- Local session history drawer (restore or delete) and settings drawer
  (streaming, auto-save, keyboard hints, reduced motion, reset).
- Keyboard accessible, ARIA labels, focus-visible styles, warm cream/ink
  design. No `alert()` calls.

## How the demo AI works

`content.js` clones the page body into a detached node, removes scripts,
styles, navigation, forms and other noise, then returns up to ~30,000
characters plus the current selection. It never modifies the live page.

`sidepanel.js` then:

1. Tokenizes the text and scores word frequency (stopwords removed) to pick
   key terms.
2. Extracts the strongest 1–3 sentences by term overlap and sentence length.
3. Detects the surface (analytics, docs, calendar, Drive, mail, CRM, commerce,
   or general web page) from the domain.
4. Detects intent from your prompt or the quick action (metrics, competitors,
   CRM, email, code, and so on) and chooses matching analysis, next step and
   action items.
5. Builds a markdown answer and types it out gradually unless reduced motion
   or streaming-off is selected.

The same input always produces the same answer body (only the "captured at"
timestamp changes). The profile and approval-mode selectors are persisted and
printed in the answer footer, but they do not contact a provider or perform
actions — this is an intentional local demo, not a live AI integration.
Suggested prompts are examples only; Keel does not connect to Google Drive,
analytics, CRM, calendar or email accounts.

## Message contract

`sidepanel.js` sends 16 message types; every one has a handler in
`background.js`: `GET_STATE`, `GET_PAGE_CONTEXT`, `GET_PENDING_ACTION`,
`CLEAR_PENDING_ACTION`, `NEW_SESSION`, `SAVE_SESSION`, `LIST_SESSIONS`,
`SAVE_SESSIONS_REPLACE`, `CLEAR_SESSIONS`, `SET_WELCOME_SEEN`, `SET_MODEL`,
`SET_APPROVAL_MODE`, `SET_SETTINGS`, `SET_MODE`, `SET_ACTIVE_TAB`, and
`SET_CONTEXT_SOURCE`. Background-only helpers (`PING`, `SET_PENDING_ACTION`,
`OPEN_PANEL`, `OPEN_TAB_GROUP`) are reserved for internal use. The worker asks
the content script for `KEEL_GET_CONTEXT` with `tabs.sendMessage` (runtime
messages cannot reach content scripts) and broadcasts `KEEL_PAGE_CHANGED` to
open panels when the active tab changes.

## What to upload to the Chrome Web Store

1. **Upload `keel/site/keel-extension.zip`** as the extension package. It
   contains `manifest.json` at the root and only the files listed above — no
   store assets, no nested folder, no ZIP inside a ZIP (~50 KB).
2. **Listing copy** from `keel/site/store-assets/store-listing.md`: title, short
   summary, full description, category and tags.
3. **Screenshots** (upload in order): `screenshot-1-chat.png`,
   `screenshot-2-chat-answer.png`, `screenshot-3-convert.png`,
   `screenshot-4-history.png`.
4. **Promo tiles**: `promo-small-440x280.png` and
   `promo-marquee-1400x560.png`.
5. **Privacy policy URL** in the store form:
   `https://keel-desktop.vercel.app/privacy`. Chrome does not accept a privacy
   policy field in `manifest.json`, so it belongs in the store listing.
6. **Support URL**: `https://keel-desktop.vercel.app/requirements`.
7. Before submitting, load the unpacked folder in Chrome and smoke-test Chat,
   Convert, History, the toolbar icon and the right-click menus on a real HTTPS
   page. Nothing in this repository publishes or deploys the extension.

## Known limitations

- Not a live model: answers are deterministic local rules, not generated by an
  LLM. The profile labels do not select a provider.
- No real dictation; the mic is a labeled simulation and records no audio.
- Quick actions are example prompts, not live integrations with third-party
  services.
- Tab grouping is available over the internal message bus but is not exposed as
  a panel button.
- `chrome://` and Web Store pages cannot be read by content scripts; HTTP and
  file pages are outside the declared match patterns. The panel degrades to
  title/URL context there.
- Session history is local to this browser profile; it does not sync with the
  Keel desktop or web app.
