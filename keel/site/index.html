How this works

  • Your key is verified against the provider live, then stored only in this browser — it never touches any Keel server (there isn't one).
  • Anything in your prompt goes to that provider, under your key — that's what BYOK means.
  • No tools, no files, no agent on this page — the agent runs in the local app.
  • “Forget this key” wipes it from this browser. Site data cleared = forgotten too.

Developer

This page has no backend by design. The local app exposes a token-gated bridge on 127.0.0.1 — health, providers, run, settings, filesystem listing, fleet routes. Read the source on GitHub:

Nothing here can call it: this page is https, the bridge is loopback-only, and none of your keys are present.

Skills

Skills load from your machine at run time — ~/.keel/skills for yours, Keel's bundled set beside them. This mirror can't see them. Install Keel and run keel doctor to list them.

Connectors

MCP servers plug tools into Keel on your machine — GitHub, filesystem, memory, sequential-thinking and more. They're managed in the local app's Providers / fleet console, not here.

Plugins

Keel does not ship a plugin runtime. Connectors — MCP — are the extension surface: one server, every surface.
