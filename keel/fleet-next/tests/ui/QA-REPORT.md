## 2. Harness created (exclusive ownership: `tests/ui/**`)

| File | Purpose |
|---|---|
| `tests/ui/verify-ui.mjs` | Self-contained Node ESM harness using only `node:` builtins. Scans all `app/**`, `components/**`, `features/**`, `lib/**` source (47 source files at the final run; the count grew during the session as other agents added files), extracts frontend bridge calls, applies static a11y / placeholder / responsive heuristics, and invokes the two Python helpers below. Writes `tests/ui/results.json`. |
| `tests/ui/route_scan.py` | Read-only scanner of `src/keel/fleet/routes.py` and `src/keel/webapp.py`; emits GET-specific and POST-specific route vocabularies as JSON so endpoint checks are evidence-backed rather than hand-written. |
| `tests/ui/probe_bridge.py` | Starts the real Python bridge on an ephemeral port (same code path as the pytest `compat_server` fixture) and probes an explicit **read-only GET** allowlist; no state is mutated. |
| `tests/ui/results.json` | Machine-readable evidence generated by the harness (regenerated on every run). |
| `tests/ui/QA-REPORT.md` | This report. |

**Run command:** `cd keel/fleet-next && node tests/ui/verify-ui.mjs`
Exit code `1` when any hard check fails, `0` otherwise. No npm dependency added, no `package.json` edit, no git staging.

**Known limitations of the harness (do not over-read a pass):**
- Static JSX/CSS heuristics can miss dynamic or unusual patterns; a pass is not a rendered-page guarantee.
- Endpoint matching uses route *vocabulary* (collections + verbs extracted from the Python dispatchers). It proves a plausible backend route exists; it does not verify payload shape, status codes or business behaviour for mutating endpoints.
- Mutating POST endpoints are **not** live-probed (they would change the user's `fleet.db`/settings). Only the 11 safe GET endpoints were probed over real HTTP.

## 7. Anything not verified, with exact reason

1. **Playwright end-to-end / screenshots / visual regression** — dependency absent; no `node_modules` at session start and `npm ls playwright @playwright/test` remains empty. Installing it would add a new dependency, which this workstream is forbidden to do.
2. **Horizontal overflow at 360×800 / 390×844 / 768×1024 / 1024×768 / 1280×800 / 1440×900** — only static CSS bounds were checked; the in-app browser has no viewport emulation and `window.resizeTo` is blocked. One real viewport (912×670) was measured: `scrollWidth === innerWidth` on all six surfaces.
3. **Computed contrast, focus order, focus restoration, dialog traps in a real DOM** — static source analysis only. (Source-level evidence exists: `Dialog` focus trap at `components/ui.tsx:160–176`.)
4. **POST endpoint behaviour, payload validation, 409/202 semantics** — deliberately not live-probed to avoid mutating the user's `fleet.db` and settings. Existence and method were checked statically against Python dispatchers.
5. **Live model round-trip / provider verification** — no provider credentials on this host (also documented in `fleet-next/README.md:101–105`).
6. **Packaged Electron/Tauri UI root assertion** — out of this workstream's scope and no packaged binary present; `keel/tests/test_packaged_ui_serving.py` skips the EXE check when absent.
7. **Full `python -m pytest -q`** — run by the lead as a regression guard: **22 failed, 2531 passed, 51 skipped, 1044 subtests passed in 452.88 s**. All 22 failures are in untouched backend/release/plan areas (missing release manifest/checksums, plan hash fixtures, tool registry, policy enforcement, session export FK, webapp upload path). No Python file was changed by the frontend workstream; these are baseline failures, not frontend regressions.
