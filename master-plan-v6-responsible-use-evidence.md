## Adversarial coverage (all green)

* **Content completeness** - every disclosure, checklist item, wizard offer,
  disclaimer paragraph and builder stop rule is present in the rendered doc;
  the checked-in `RESPONSIBLE-USE.md` is asserted *exactly equal* to
  `render_document()`, so the doc cannot drift from the typed data. Sections,
  first-run notice and known-limits references are asserted separately.
* **No false security guarantees** - a locally defined list of affirmative
  promise phrases (e.g. "guaranteed isolation", "fully isolated", "no risk",
  "sandbox guarantees") is checked against every string in the data and the
  rendered doc; the exact limiting sentence and "sole control" must appear in
  all rendered copy. The disclaimer is checked to be a warranty/liability
  limitation, not a safety promise.
* **Fail-closed D5.5 rule** - a retry is authorised only when all conditions
  hold: recognised dev-sandbox cause (credentials/network/IPC), non-blank
  evidence, unchanged command, and exactly the narrowest typed escalation.
  Thirteen negative cases (no evidence, blank evidence, unknown/no/other
  cause, real test failure, bypass tests, bypass product sandbox, changed
  command, absent/broader/wrong escalation, string `"all"` and
  `"full-unsandboxed"`) all stop with `Escalation.NONE`, no evidence and a
  written reason. A bypass attempt with perfect evidence still stops.
* **No silent downgrade is representable** - `Escalation` has no `all`,
  `full`, `off`, `unsandbox` or `bypass` member; every rejection goes through
  `fail_closed()` and carries a reason. STOP decisions never carry escalation
  or evidence forward.
* **Typed/pure data** - all records are frozen dataclasses (mutation attempts
  raise `FrozenInstanceError`), serialise to plain JSON, and the module source
  is checked for host/network/clock/chance imports.

## Design notes

* **One source of truth for copy.** The prose in `RESPONSIBLE-USE.md` is
  rendered from the same immutable objects that a first-run notice (W1.10),
  known-limits page (W7.19) and onboarding wizard (V17) would consume. A test
  asserts exact equality, so editing the doc alone is detected.
* **The limitation sentence is verbatim.** D5.2's required wording appears
  unchanged in `SANDBOX_LIMITS_DISCLOSURE.text` and is reused everywhere;
  tests also assert that no affirmative guarantee phrasing is introduced.
* **Escalation is a scope, never a switch.** `Escalation` models one
  dev-sandbox resource per value. The product sandbox and the test suite are
  outside its domain entirely, which is why a bypass flag can only produce a
  STOP.
* **The D5.5 default is deny.** `evaluate_failure` takes
  `escalation=Escalation.NONE` by default, so a caller must explicitly supply
  the narrowest scope derived from the evidenced resource. Unknown resource
  labels map to `Escalation.NONE` before any other check.
* **Legal status is explicit.** The D5.4 copy references the distribution's
  license agreement (EULA; project metadata is `Proprietary`) and is marked
  as a draft for G5 legal review, so it is not mistaken for final legal text.
